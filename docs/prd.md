# COPD 可视化教学平台与创新实践 PRD

**版本**：V3.0（最终草案）  
**文档状态**：需求基线，供后续 `design.md`、`architecture.md` 与 `readme.md` 讨论使用  
**产品形态**：Web 教学平台  
**核心定位**：基于病理标本的“形态 - 机制 - 临床”贯通式教学平台

## 1. 产品概述

### 1.1 背景与问题

COPD 的学习需要同时理解大体病变、镜下形态、发病机制及其临床后果。传统图文教学往往将这些内容割裂，学生能记住单个知识点，却难以建立从形态到机制、再到诊断与治疗的完整认知链。

本平台以 COPD 病理标本为学习锚点，将大体标本、镜下切片、机制推导和 AI 辅助诊断串联起来，让学生在观察、推理和实践中完成知识迁移。

### 1.2 产品定位

平台面向医学相关专业学生，提供一个以交互式病理标本为核心的 COPD 可视化学习与实践环境：

- 通过大体标本与镜下切片联动，建立形态认知；
- 通过机制链条，把病理改变推导到肺功能和临床表现；
- 通过 DeepSeek 智能诊断，检验学生的综合分析能力；
- 强制将 AI 分析结果关联回具体病理标本，形成教学闭环。

### 1.3 差异化优势

1. **大体标本与镜下切片联动可视化**：点击大体标本的病变区域，即时查看对应镜下证据。
2. **形态 - 机制 - 临床贯通**：每个关键病理改变均可展开机制、功能变化、症状、治疗靶点和危险因素推导。
3. **DeepSeek 多模态智能诊断方向**：MVP 先支持文本输入，后续扩展肺功能报告或 CT 截图识别；AI 输出必须回溯病理基础并跳转至标本锚点。

## 2. 产品目标与成功标准

### 2.1 项目目标

构建一个可运行的 Web 平台，使学生能够：

- 识别 COPD 典型大体和镜下病理改变；
- 解释关键病理改变背后的发病机制；
- 将机制推导到肺功能变化、症状、治疗和预防；
- 使用 AI 辅助诊断模块分析 COPD 疑似病例，并将结论与病理标本对应起来。

### 2.2 MVP 成功标准

- 学生可以在一张高清 COPD 大体标本图上识别并点击至少 3 个热区；
- 每个热区可加载对应镜下切片，并展示关键病理标注；
- 镜下切片支持缩放和拖拽查看；
- 至少提供 2 - 3 条可交互的核心机制通路；
- 学生提交文本病例后，系统能返回固定结构的 AI 分析，并包含“病理基础”和“病理标本关联”；
- AI 结果中的标本关联可点击并跳转到模块 1 的对应热区或切片；
- 关键教学流程可在一次会话内完成：标本观察 → 机制推导 → AI 诊断 → 回看标本。

## 3. 用户与使用场景

### 3.1 目标用户

- **主要用户**：医学相关专业学生，用于课前预习、课堂学习和课后复习。
- **教学支持者**：教师或教研人员，负责病理资源、标注和机制内容的维护（MVP 可先通过静态数据完成）。

### 3.2 典型使用场景

1. 学生进入平台，观察 COPD 大体标本及其热区。
2. 点击“胸膜下肺大疱”等热区，查看对应镜下切片和病理标注。
3. 点击“肺泡壁断裂”等标注，阅读发病机制及临床推导链。
4. 进入诊断模块，输入临床描述和肺功能结果。
5. 查看 DeepSeek 的结构化分析，点击其中的标本关联链接回到对应病理证据。

## 4. 产品范围

### 4.1 MVP 范围

- 1 张高清 COPD 大体标本图；
- 3 - 5 张对应镜下切片图；
- 大体标本热区点击和悬停提示；
- 镜下切片标注、缩放和拖拽；
- 2 - 3 条核心机制通路的动态或分步展示；
- 每个机制卡片对应的临床推导链；
- DeepSeek 文本病例分析；
- AI 输出中的病理标本锚点链接；
- 基于 React/Vue、Python FastAPI 和 DeepSeek OpenAI 兼容接口的基础实现。

### 4.2 后续迭代方向

- 肺功能报告截图和 CT 描述的图像识别；
- 更丰富的病例库、练习题和学习记录；
- 3D 标本或肺部结构可视化（如确有必要再引入 Three.js）；
- 教师端内容管理和标注工具；
- 学习效果统计、错题反馈和课程管理。

### 4.3 明确不纳入 MVP 的内容

- 面向真实患者的医疗诊断或治疗决策；
- 复杂的用户权限、课程商城和社交功能；
- 由平台自动生成或替代医学专家审核的病理标注；
- 肺功能报告/CT 图片的多模态识别（作为 V1.0 或后续能力）。

## 5. 功能需求

### 5.1 模块总览

| 模块 | 核心价值 | MVP 实现 |
| --- | --- | --- |
| 1. 病理标本联动可视化 | 以大体病变为入口，联动镜下证据 | 1 张高清大体图 + 3 - 5 张对应镜下图 + 点击热区联动 |
| 2. 发病机制动态演示 | 将病理改变转化为机制理解 | 预设文本、节点和箭头动画，覆盖 2 - 3 条核心通路 |
| 3. 临床推导模块 | 从机制延伸至肺功能、症状、治疗和预防 | 机制卡片下提供可展开的推导链条 |
| 4. DeepSeek 智能诊断 | 检验综合应用并回归病理基础 | 文本输入 + 结构化分析 + 标本锚点链接 |

### 5.2 模块 1：病理标本联动可视化（核心亮点）

#### 页面布局

```text
┌─────────────────────────────────────────────┐
│  左侧：大体标本图          右侧：镜下切片图      │
│  (高清 COPD 尸检肺照片)   (当前选中区域的切片)  │
│                           - 可深度缩放        │
│  [点击热区1：肺大疱]      - 标注：肺泡壁断裂   │
│  [点击热区2：气道壁]      - 标注：黏液腺增生   │
│  [点击热区3：肺尖]        - 标注：肺气肿囊腔   │
│                           - 标注：炭末沉着    │
└─────────────────────────────────────────────┘
│  下方：机制推导区                            │
│  [当前选中的病理改变] → [发病机制] → [临床表现]  │
│  肺泡壁断裂          → 弹性蛋白酶失衡 → 肺气肿   │
│                      → FEV1↓      → 呼吸困难  │
│                      → 治疗靶点    → 支气管扩张剂│
│                      → 危险因素    → 吸烟！    │
└─────────────────────────────────────────────┘
```

#### 交互需求

1. 页面展示带热区标注的大体 COPD 标本图。
2. 鼠标悬停热区时显示区域名称，例如“胸膜下肺大疱”。
3. 点击热区后，右侧加载该区域对应的镜下切片。
4. 镜下切片自动展示关键病理标注，例如“肺泡壁断裂”“黏液腺增生”“肺气肿囊腔”“炭末沉着”。
5. 学生可以在镜下切片上滚轮缩放、拖拽平移，观察细胞级改变。
6. 选择病理标注后，下方自动展开该病变对应的完整推导链。
7. 大体标本热区、镜下切片、机制卡片和 AI 结果之间使用稳定锚点互相跳转。

#### MVP 热区与内容建议

| 热区示例 | 对应镜下内容 | 主要教学关联 |
| --- | --- | --- |
| 胸膜下肺大疱 | 肺泡壁断裂、肺气肿囊腔 | 弹性纤维破坏、肺气肿、呼吸困难 |
| 气道壁 | 黏液腺增生、气道炎症 | 分泌物增多、气流受限、咳嗽咳痰 |
| 肺尖/炭末沉着区域 | 炭末沉着、局部结构改变 | 吸烟和颗粒暴露等危险因素 |

### 5.3 模块 2：发病机制动态演示

#### 功能需求

- 从当前选中的病理改变进入机制卡片；
- 以节点和箭头展示病理改变 → 分子/细胞机制 → 组织结构变化 → 功能变化；
- 支持自动播放或逐步点击；
- 关键节点可附简短解释，避免只展示结论。

#### MVP 核心机制示例

```text
α1-抗胰蛋白酶缺乏
  → 弹性蛋白酶活性升高
  → 肺泡壁弹性纤维破坏
  → 肺泡壁断裂与肺气肿形成
```

至少整理 2 - 3 条核心通路，内容需经病理学教材或教师审核。

### 5.4 模块 3：临床推导模块

#### 功能需求

每个病理/机制卡片下提供可展开的推导链，至少覆盖：

- 肺功能变化：如 FEV1 下降、FEV1/FVC 下降；
- 临床表现：如活动后气促、慢性咳嗽、咳痰；
- 治疗靶点：如支气管扩张剂等；
- 危险因素和预防：如吸烟、颗粒物暴露控制。

#### 示例推导

```text
肺泡壁断裂
  → 弹性回缩力下降、气体交换面积减少
  → FEV1 下降、呼吸困难
  → 支气管扩张剂及危险因素控制
  → 重点预防：戒烟、减少有害颗粒暴露
```

### 5.5 模块 4：DeepSeek 智能诊断

#### 产品定位

该模块用于学生学完病理后的综合实践。AI 不仅输出诊断判断，还必须解释临床表现对应的病理基础，并回链至模块 1 的具体标本。

#### MVP 输入

支持学生输入一段文本病例，例如：

> 患者，男，68 岁，吸烟 50 年，活动后气促 5 年。肺功能：FEV1/FVC=58%，FEV1 占预计值 48%。胸部 CT 示双肺透亮度增高，可见多发无壁透亮区。

V1.0 再扩展肺功能报告截图、CT 截图等图像输入；MVP 不要求图像识别。

#### AI 输出结构

系统要求 DeepSeek 严格按以下结构返回：

1. **诊断判断**：是否符合 COPD 诊断；如信息允许，给出 GOLD 分级及分组，并说明依据和不确定性。
2. **病理基础溯源**：
   - 大体标本层面：肺脏外观改变；
   - 镜下切片层面：肺泡、气道、血管的病理改变；
   - 发病机制：从分子机制解释这些改变如何发生。
3. **治疗与预防推导**：基于上述病理机制推导治疗靶点和危险因素控制策略。
4. **病理标本关联**：关联至教学平台中的具体标本锚点，并提示学生观察对应病变。

#### Prompt 基线

```text
你是一位呼吸科病理-临床整合教学导师。学生将提供一段 COPD 疑似病例的描述。

【学生输入】
{student_input}

请你严格按以下结构输出分析：
1.【诊断判断】：该病例是否符合 COPD 诊断？属于 GOLD 几级？分组是什么？请说明依据和不确定性。
2.【病理基础溯源】：请详细解释该病例临床表现背后的病理改变，必须包括：
   - 大体标本层面：肺脏外观会有什么改变？
   - 镜下切片层面：肺泡、气道、血管分别有什么病理改变？
   - 发病机制：从分子机制解释这些改变如何发生。
3.【治疗与预防推导】：基于上述病理机制，推导治疗靶点和危险因素控制策略。
4.【病理标本关联】：请将你的分析关联到教学平台病理标本模块中的以下标本：
   - [肺大疱标本热区]
   - [肺泡壁断裂切片]
   - [黏液腺增生切片]
   提示学生在对应标本中观察你描述的病理改变。

请用专业但易于理解的语言，帮助学生建立“形态-机制-临床”的完整认知链。
```

#### 前端展示与教学闭环

- AI 返回结果按四个固定部分分区展示；
- “病理标本关联”中的标本名称渲染为可点击链接；
- 点击链接后跳转模块 1，并自动选中对应大体热区、镜下切片或标注；
- 对输入信息不足、诊断不确定或超出教学范围的情况，界面明确提示“仅供教学参考，不构成医疗建议”。

## 6. 内容与资源需求

| 资源 | 数量 | 内容要求 | 获取/制作建议 |
| --- | --- | --- | --- |
| COPD 大体标本高清照片 | 1 张起 | 能清楚呈现肺大疱、肺尖等可讲解区域 | 病理学教研室、解剖学图谱或开放医学图像库；核验版权 |
| 对应镜下切片高清图像 | 3 - 5 张 | 覆盖肺泡壁断裂、黏液腺增生、气道炎症、血管重塑、炭末沉着等 | 优先使用与大体标本可建立对应关系的切片 |
| 病理标注数据 | 每张切片 3 - 5 个标注 | 标注区域、名称、说明和稳定锚点 | 由教师或具备医学背景的成员审核 |
| 机制推导内容 | 每条通路 4 - 5 个节点 | 病理改变、机制、功能、临床、治疗/预防节点 | 参考《病理学》等教材并完成内容审核 |
| 标本锚点映射 | 每个可关联病变 1 个稳定 ID | 热区、切片、标注和 AI 链接可互相定位 | 在内容建模阶段统一维护 |

### 6.1 资源不足时的原型策略

- 使用公开数据库中带标注的病理图像快速验证交互逻辑；
- 使用示意图或手绘风格占位素材先完成页面和联动流程；
- 所有占位素材需明确标识“示例/待替换”，上线前替换为已获授权且经审核的资源。

## 7. 技术约束与实现边界

### 7.1 技术方案

- **前端**：React 或 Vue；
- **可视化**：常规二维联动优先使用图片/SVG，只有确有 3D 需求时再引入 Three.js；
- **后端**：Python FastAPI；
- **AI 接入**：使用 DeepSeek 的 OpenAI 兼容接口/SDK；
- **热区联动**：纯前端实现，使用图片绝对定位的透明可点击区域或 SVG 标注；
- **切片查看**：支持高分辨率图片的缩放、平移和标注叠加。

### 7.2 关键实现约束

- DeepSeek API 密钥只能由后端保管，前端不得直接暴露密钥；
- AI 输出必须经过结构化解析或稳定的标记约定，确保病理标本链接可被前端可靠识别；
- 标本、切片、标注、机制节点和锚点使用稳定 ID，避免内容更新后链接失效；
- 医学内容和 AI Prompt 需支持版本管理，便于教学审核和后续迭代；
- 平台定位为教学工具，不能将 AI 输出展示为真实医疗诊断。

## 8. 质量与验收要求

### 8.1 功能验收

- 热区悬停、点击、切片加载、标注展示、缩放和拖拽均可用；
- 切换热区时，右侧切片和下方机制/临床内容同步更新；
- AI 模块能够接受文本病例并返回四段结构化结果；
- 病理标本关联链接能够正确跳转至目标锚点；
- API 异常、空输入、超时和无法解析的 AI 输出有明确错误提示和降级处理。

### 8.2 内容验收

- 关键病理标注和机制链条经医学背景人员审核；
- 每个教学标本均有来源、版权/授权状态和内容说明；
- AI 展示内容包含教学免责声明，并对不确定结论进行提示。

### 8.3 体验验收

- 首屏能明确说明“观察标本 → 推导机制 → AI 实践”的学习路径；
- 热区名称、镜下标注、机制节点和临床结论的视觉层级清晰；
- 高分辨率切片在常见桌面浏览器中可流畅缩放和拖拽；
- AI 结果中的关联链接具有明显的可点击样式和返回路径。

## 10. 风险与应对

| 风险 | 影响 | 应对策略 |
| --- | --- | --- |
| 高清标本资源不足或版权不清 | 无法上线或无法建立真实联动 | 原型阶段使用占位/开放资源；上线前完成授权核验 |
| 大体标本与切片无法一一对应 | 破坏核心教学逻辑 | 优先选择可追溯的配对资源，并为每个锚点建立映射 |
| 医学内容或标注存在错误 | 误导学习 | 引入教师/医学背景人员审核，记录内容版本 |
| AI 输出格式不稳定 | 标本链接无法渲染，教学链路中断 | 固定 Prompt、结构化协议、后端校验和失败降级 |
| AI 产生过度确定的诊断结论 | 产生医疗误用风险 | 明确教学免责声明，展示依据与不确定性，不支持真实医疗决策 |
| 高分辨率图片加载缓慢 | 影响观察体验 | 图片压缩/切片金字塔、懒加载和 CDN/静态资源优化 |
